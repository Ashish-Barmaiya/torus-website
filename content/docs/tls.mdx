# TLS

Torus can terminate HTTPS connections at the edge, allowing backend services to receive normal HTTP traffic while clients communicate securely over TLS.

TLS termination is configured entirely through the YAML configuration file and is enabled when certificate and private key files are provided.

The encrypted connection ends at Torus.

---

## Responsibilities

When TLS is enabled, Torus is responsible for:

- accepting HTTPS connections
- loading certificates
- performing TLS handshakes
- decrypting incoming traffic
- forwarding requests to backend services
- encrypting responses before returning them to clients

Routing and backend selection remain unchanged.

---

## Enabling TLS

TLS is configured through the `tls` section.

Example:

```yaml
server:
  addr: ":8443"

  tls:
    cert_file: cert.pem
    key_file: key.pem
    min_version: "1.2"
```

When both certificate and key files are present, Torus starts an HTTPS listener instead of a plain HTTP listener.

---

## Certificate loading

During startup Torus loads:

- the server certificate
- the corresponding private key

Startup fails if:

- either file is missing
- the certificate is invalid
- the private key cannot be loaded
- the certificate and key do not match

This prevents the proxy from starting in an invalid state.

---

## Minimum TLS version

The minimum supported TLS protocol version can be configured.

For production deployments, newer protocol versions should be preferred whenever possible.

The exact supported values are documented in the **Configuration Reference**.

## Performance considerations

TLS introduces additional work compared to plain HTTP.

Typical overhead includes:

- TLS handshake
- certificate validation
- encryption
- decryption

Benchmark-002 evaluates the impact of TLS termination on throughput, latency, CPU utilization, and memory usage.

---

## Failure behavior

TLS connections are rejected when:

- certificate loading fails
- the private key is invalid
- protocol negotiation fails
- the client does not support the configured minimum TLS version

These failures occur before request routing begins.

---

## Design rationale

TLS termination allows backend services to remain simple while providing secure client communication at the edge.

Centralizing TLS management also simplifies:

- certificate rotation
- deployment
- observability
- operational management
