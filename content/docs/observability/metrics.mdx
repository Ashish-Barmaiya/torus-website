# Metrics

Torus exports metrics in the Prometheus exposition format, allowing the behavior of a running proxy to be monitored continuously.

Unlike logs, which describe individual events, metrics provide quantitative measurements that can be aggregated, visualized, and alerted on over time.

Torus exposes three categories of metrics:

- **Application metrics** implemented by Torus itself.
- **Go runtime metrics** exported by the Prometheus Go collector.
- **Process metrics** exported by the Prometheus process collector.

---

## Metrics architecture

```text
               Torus
                 │
      - Application Metrics
      - Go Runtime Metrics
      - Process Metrics
                 ↓
          /metrics endpoint
                 ↓
            Prometheus
                 ↓
              Grafana
```

The three metric categories complement each other by exposing application behavior, runtime characteristics, and process resource usage.

---

# Application metrics

Application metrics describe the behavior of Torus itself.

These metrics are grouped into HTTP, backend, and runtime categories.

---

## HTTP metrics

### `torus_http_requests_total`

**Type:** Counter

**Labels**

- `method`
- `route`
- `status`

Counts every HTTP request processed by Torus.

---

### `torus_http_request_duration_seconds`

**Type:** Histogram

**Labels**

- `method`
- `route`

Measures end-to-end request latency through the proxy.

Histogram buckets:

- 100 µs
- 250 µs
- 500 µs
- 1 ms
- 2.5 ms
- 5 ms
- 10 ms
- 25 ms
- 50 ms
- 100 ms
- 250 ms
- 500 ms
- 1 s

---

### `torus_http_requests_in_flight`

**Type:** Gauge

Tracks the number of requests currently being processed.

---

## Backend metrics

Backend metrics are recorded independently for every configured upstream.

### `torus_backend_requests_total`

**Type:** Counter

**Labels**

- `backend`

Counts requests forwarded to each backend.

---

### `torus_backend_request_duration_seconds`

**Type:** Histogram

**Labels**

- `backend`

Measures backend response latency.

Histogram buckets:

- 100 µs
- 250 µs
- 500 µs
- 1 ms
- 2.5 ms
- 5 ms
- 10 ms
- 25 ms
- 50 ms
- 100 ms
- 250 ms
- 500 ms
- 1 s

---

### `torus_backend_errors_total`

**Type:** Counter

**Labels**

- `backend`

Counts forwarding failures for each backend.

---

### `torus_backend_up`

**Type:** Gauge

**Labels**

- `backend`

Represents backend health.

| Value | Meaning   |
| ----: | --------- |
|   `1` | Healthy   |
|   `0` | Unhealthy |

---

## Runtime metrics

Runtime metrics describe the internal operation of Torus.

### `torus_runtime_reloads_total`

**Type:** Counter

**Labels**

- `result`

Possible values:

- `success`
- `failure`

Counts configuration reload attempts.

---

### `torus_runtime_generation`

**Type:** Gauge

Represents the currently active immutable runtime generation.

---

### `torus_runtime_build_duration_seconds`

**Type:** Histogram

Measures the time required to construct a new runtime during startup or configuration reload.

Histogram buckets:

- 1 ms
- 2.5 ms
- 5 ms
- 10 ms
- 25 ms
- 50 ms
- 100 ms
- 250 ms
- 500 ms
- 1 s
- 2.5 s
- 5 s

---

# Go runtime metrics

In addition to Torus-specific metrics, the `/metrics` endpoint exports the standard metrics provided by Prometheus' Go collector.

These describe the behavior of the Go runtime itself.

Examples include:

### Goroutines

- `go_goroutines`

### Heap

- `go_memstats_heap_alloc_bytes`
- `go_memstats_heap_inuse_bytes`
- `go_memstats_heap_idle_bytes`
- `go_memstats_heap_objects`

### Memory allocation

- `go_memstats_alloc_bytes`
- `go_memstats_alloc_bytes_total`

### Garbage collection

- `go_gc_duration_seconds`
- `go_gc_gogc_percent`
- `go_gc_gomemlimit_bytes`
- `go_memstats_next_gc_bytes`
- `go_memstats_last_gc_time_seconds`

### Runtime

- `go_threads`
- `go_info`

The Go collector exports many additional runtime statistics beyond those listed above.

---

# Process metrics

Process metrics are exported through the Prometheus process collector.

These describe the operating system process running Torus.

Examples include:

### CPU

- `process_cpu_seconds_total`

### Memory

- `process_resident_memory_bytes`
- `process_virtual_memory_bytes`
- `process_virtual_memory_max_bytes`

### Process information

- `process_open_fds`
- `process_max_fds`
- `process_start_time_seconds`

The exact set of process metrics may vary depending on the operating system.

---

## Why three metric categories?

Each metric category answers different operational questions.

| Category    | Purpose                                       |
| ----------- | --------------------------------------------- |
| Application | How Torus is behaving.                        |
| Go runtime  | How the Go runtime is behaving.               |
| Process     | How many system resources Torus is consuming. |

Together, they provide a comprehensive view of proxy behavior, runtime characteristics, and process health.
