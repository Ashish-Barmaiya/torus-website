# Deployment

Torus is designed to run as a standalone server process.

Once started, it accepts incoming HTTP or HTTPS traffic, forwards requests to configured backend services, continuously monitors backend health, and applies configuration changes without interrupting active requests.

The deployment model is intentionally simple. Torus requires only a configuration file and access to its upstream services.

---

## Deployment model

A typical production deployment looks like:

```text
                    Internet
                        ↓
                 Load Balancer
                        ↓
                    Torus Proxy
                        │
         ┌────────┴─────────┐
         ↓                             ↓
     Backend A                     Backend B
```

Torus acts as the edge proxy between clients and backend applications.

---

## Deployment requirements

Before deploying Torus, ensure:

- a production configuration file is available
- upstream services are reachable
- health endpoints are configured
- firewall rules allow inbound traffic
- TLS certificates are available (if HTTPS is enabled)

---

## Runtime behavior

During normal operation Torus:

- listens for incoming connections
- routes requests
- performs load balancing
- monitors backend health
- exports operational metrics
- reloads configuration without restarting

No manual intervention is required after startup under normal conditions.

---

## Deployment options

Torus can be deployed in several environments.

| Environment  | Recommended when               |
| ------------ | ------------------------------ |
| Docker       | Containerized workloads        |
| Linux        | Bare-metal or virtual machines |
| systemd      | Long-running Linux services    |
| Oracle Cloud | Cloud VM deployments           |

Each deployment model is documented separately.

---

## Production checklist

Before exposing Torus to production traffic:

- Build using a released version of Go.
- Use a validated production configuration.
- Enable health checks for every backend.
- Configure TLS for public endpoints.
- Enable metrics and request logging.
- Run the complete test suite before deployment.
- Verify readiness using `/readyz`.
- Monitor runtime metrics after startup.

---

## Updating configuration

Configuration changes do not require restarting Torus.

Instead:

```text
Configuration Updated

          ↓

 Build New Runtime

          ↓

 Atomic Runtime Swap

          ↓

 Continue Serving Traffic
```

This enables operational changes with no interruption to active requests.

---

## Choosing a deployment model

The recommended deployment depends on the operating environment.

- **Docker** for container platforms.
- **Linux** for direct host deployments.
- **systemd** for production Linux servers.
- **Oracle Cloud** for cloud virtual machines.

The underlying Torus binary behaves identically in every environment.
