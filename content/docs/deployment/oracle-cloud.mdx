# Oracle Cloud

Oracle Cloud Infrastructure (OCI) provides an inexpensive platform for hosting Torus on virtual machines.

A typical deployment consists of a Compute Instance running Torus with one or more backend services reachable over a private or public network.

---

## Deployment architecture

```text
                Internet
                    ↓
        OCI Security List / NSG
                    ↓
          Oracle Cloud Compute VM
                    │
              +-------------+
              |    Torus    |
              +-------------+
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
   Backend Service A      Backend Service B
```

---

## Prerequisites

Before deploying Torus, ensure that you have:

- an Oracle Cloud account
- a Compute Instance running Linux
- SSH access to the instance
- a compiled Torus binary
- a valid Torus configuration file

---

## Copy the binary

Transfer the compiled binary to the VM.

```bash
scp torus ubuntu@<public-ip>:/home/ubuntu/
```

Or build directly on the server.

```bash
go build -o torus ./cmd/torus
```

---

## Install Torus

Move the executable into a standard system location.

```bash
sudo mv torus /usr/local/bin/
sudo chmod 755 /usr/local/bin/torus
```

---

## Install the configuration

Create the configuration directory.

```bash
sudo mkdir -p /etc/torus
```

Copy the configuration.

```bash
sudo cp configs/torus-http.yaml /etc/torus/torus.yaml
```

---

## Open network ports

Allow inbound traffic for the ports used by Torus.

Common examples:

| Service | Port |
| ------- | ---: |
| HTTP    | 8080 |
| HTTPS   | 8443 |

Remember that OCI requires both:

- Security List (or Network Security Group) rules
- Linux firewall rules (if enabled)

---

## Verify connectivity

Check that Torus is reachable.

```bash
curl http://localhost:8080/readyz
```

From another machine:

```bash
curl http://<public-ip>:8080/readyz
```

A successful response confirms that networking and firewall configuration are correct.

---

## Running as a service

For production environments, manage Torus using **systemd**.

This provides:

- automatic startup after reboot
- service supervision
- centralized logging
- automatic restart after failures

Refer to the **systemd** deployment guide for the recommended service configuration.

---

## TLS

For Internet-facing deployments:

- enable HTTPS
- install trusted certificates
- disable unused ports
- redirect HTTP traffic when appropriate

Certificate paths should reference files stored on the VM.

---

## Monitoring

After deployment, monitor:

- `/readyz`
- `/metrics`
- request logs
- system resource usage

Operational visibility becomes increasingly important as traffic grows.

---

## Production recommendations

For reliable production deployments:

- use a dedicated service account
- restrict firewall rules to required ports
- enable HTTPS
- configure backend health checks
- monitor Prometheus metrics
- keep regular backups of configuration files
- update the operating system regularly
