# Observability

The `observability` section controls whether Torus exposes Prometheus metrics.

When enabled, Torus exposes `/metrics`, which Prometheus can scrape. The configuration controls the Torus endpoint; installing and operating Prometheus or Grafana remains a deployment concern.

```yaml
observability:
  enabled: true
```


## Configuration

The `observability` section currently supports a single field.

| Field     | Type    | Required | Description                 |
| --------- | ------- | -------- | --------------------------- |
| `enabled` | boolean | No       | Enables Prometheus metrics. |


## Enabling observability

To expose metrics, set:

```yaml
observability:
  enabled: true
```

When enabled, Torus exposes:

```text
GET /metrics
```

## Disabling observability

To omit the endpoint, set:

```yaml
observability:
  enabled: false
```

When disabled:

- the `/metrics` endpoint is not registered
- normal proxy operation, health checks, and logging continue independently.

## Prometheus integration

A Prometheus job can scrape the configured Torus listener:

```yaml
scrape_configs:
  - job_name: torus
    static_configs:
      - targets:
          - host.docker.internal:8080
```

The target must match the listener used by the deployment. The repository's Docker stack includes local Prometheus and Grafana assets under `docker/`; see [Docker](/docs/deployment/docker).

## Verify metrics

With observability enabled, request the endpoint on the configured listener:

```bash
curl http://localhost:8080/metrics
```

It returns Prometheus exposition-format metrics. Prometheus collects those metrics and Grafana visualizes the data; neither is configured by the `observability` block itself.
