# Configuration Overview

Torus is configured entirely through a declarative YAML configuration file.

The configuration describes the desired state of the proxy, including how it listens for requests, where traffic is routed, how backend health is monitored, whether TLS is enabled, and whether observability features are active.

During startup, Torus reads the configuration, validates it, and constructs an immutable runtime from it. The configuration file is never consulted while serving requests.

## Configuration lifecycle

Every configuration follows the same lifecycle.

If a configuration is invalid, Torus does not construct a runtime from it. During a reload, the existing runtime remains active when the replacement cannot be parsed, validated, or constructed.

---

## Configuration structure

A typical configuration consists of the following sections.

| Section         | Purpose                                      |
| --------------- | -------------------------------------------- |
| `apiVersion`    | Identifies the configuration schema version. |
| `server`        | Configures the address on which Torus listens. |
| `services`      | Defines logical services and their upstream pools. |
| `routes`        | Maps request path prefixes to services. |
| `health`        | Configures active health checks for upstreams. |
| `tls`           | Optionally enables TLS termination. |
| `observability` | Optionally enables Prometheus metrics. |

Each section configures one aspect of the runtime.
