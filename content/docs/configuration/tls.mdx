# TLS

Torus can terminate HTTPS connections by loading an X.509 certificate and private key during startup.

TLS is **optional**. If the `tls` section is omitted, Torus serves plain HTTP. When present, Torus validates the TLS configuration before accepting client connections.

Torus performs **TLS termination**. Client connections are encrypted up to Torus, after which requests are processed normally and forwarded to the configured upstream backends. Communication between Torus and upstream services is independent of client-side TLS and depends on the configured upstream URLs.

```yaml
tls:
  cert_file: "configs/cert.pem"
  key_file: "configs/key.pem"
  min_version: "1.2"
```

---

## Configuration

The `tls` section supports the following fields.

| Field         | Type   | Required | Description                                       |
| ------------- | ------ | -------- | ------------------------------------------------- |
| `cert_file`   | string | Yes      | Path to the X.509 certificate.                    |
| `key_file`    | string | Yes      | Path to the corresponding private key.            |
| `min_version` | string | No       | Minimum supported TLS version. Defaults to `1.2`. |

---

## Certificate and key

Torus requires both a certificate and its matching private key.

```yaml
tls:
  cert_file: "configs/cert.pem"
  key_file: "configs/key.pem"
```

During startup (or configuration reload), Torus loads the certificate pair using Go's standard TLS library.

If either file cannot be loaded, startup fails or the configuration reload is rejected.

---

## Minimum TLS version

The optional `min_version` field controls the minimum TLS protocol version accepted by the server.

Supported values are:

| Value   | Description        |
| ------- | ------------------ |
| `"1.2"` | TLS 1.2 and newer. |
| `"1.3"` | TLS 1.3 only.      |

If omitted, Torus defaults to TLS 1.2.

```yaml
tls:
  cert_file: "configs/cert.pem"
  key_file: "configs/key.pem"
  min_version: "1.3"
```

Any other value is rejected during configuration validation.

---

## Validation

Before a runtime is built, Torus validates the TLS configuration.

The following conditions must be satisfied:

- `cert_file` must not be empty.
- `key_file` must not be empty.
- `min_version` must be one of:
  - `1.2`
  - `1.3`

If validation succeeds, Torus attempts to load the certificate pair. Configuration loading fails if the certificate or key cannot be read or if they do not form a valid pair.

---

## HTTP configuration

To serve plain HTTP, simply omit the `tls` section.

```yaml
server:
  addr: ":8080"
```

No additional configuration is required.

---

## HTTPS configuration

To enable HTTPS, provide a valid certificate and key.

```yaml
server:
  addr: ":8443"

tls:
  cert_file: "configs/cert.pem"
  key_file: "configs/key.pem"
  min_version: "1.2"
```

Once loaded successfully, Torus accepts encrypted client connections on the configured listening address.

---

## Generating a self-signed certificate

For local development, OpenSSL can be used to generate a self-signed certificate.

```bash
openssl req \
  -x509 \
  -newkey rsa:4096 \
  -nodes \
  -keyout configs/key.pem \
  -out configs/cert.pem \
  -days 365
```

These certificates are suitable for development and testing but should **not** be used in production.

---

## Production recommendations

For production deployments:

- Use certificates issued by a trusted Certificate Authority (CA).
- Protect private key files with appropriate filesystem permissions.
- Store certificates outside the application source code when possible.
- Prefer TLS 1.3 when client compatibility allows.
