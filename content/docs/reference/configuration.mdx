# Configuration Reference

This page defines the complete **v2** Torus configuration schema. Configuration files are written in YAML and validated before Torus constructs a runtime. Invalid configurations prevent startup or are rejected during configuration reload.

---

## Configuration structure

```yaml
apiVersion: v2

server:
  addr: ":8443"

tls:
  cert_file: "configs/cert.pem"
  key_file: "configs/key.pem"
  min_version: "1.2"

health:
  interval_ms: 5000
  timeout_ms: 2000
  path: /health

observability:
  enabled: true

services:
  - name: api
    upstreams:
      - http://localhost:3001
      - http://localhost:3002

routes:
  - path: /api
    service: api
```

| Section         | Purpose                                                    |
| --------------- | ---------------------------------------------------------- |
| `apiVersion`    | Declares the configuration schema version.                 |
| `server`        | Configures the listener address.                           |
| `tls`           | Optionally enables HTTPS termination.                      |
| `health`        | Configures active backend health checks.                   |
| `observability` | Enables or disables Prometheus metrics.                    |
| `services`      | Defines logical services and their upstream backend pools. |
| `routes`        | Maps request path prefixes to services.                    |

In v2, routes reference a logical service. Upstream URLs belong to that service; they are no longer configured directly on a route.

---

## `apiVersion`

| Property        | Value    |
| --------------- | -------- |
| Type            | `string` |
| Required        | Yes      |
| Supported value | `v2`     |

```yaml
apiVersion: v2
```

Torus validates the schema version before it builds a runtime. Earlier `v1` configuration is not the current schema.

---

## `server`

The `server` section defines the address on which Torus accepts incoming requests.

### `server.addr`

| Property | Value    |
| -------- | -------- |
| Type     | `string` |
| Required | Yes      |

```yaml
server:
  addr: ":8443"
```

The address uses Go's standard `host:port` form. It must not be empty.

---

## `tls`

The `tls` section is optional. When omitted, Torus serves HTTP; when configured, Torus loads an X.509 certificate and private key to terminate HTTPS connections.

| Field         | Type   | Required                   | Default | Description                            |
| ------------- | ------ | -------------------------- | ------- | -------------------------------------- |
| `cert_file`   | string | Yes, when `tls` is present | —       | Path to the X.509 certificate.         |
| `key_file`    | string | Yes, when `tls` is present | —       | Path to the corresponding private key. |
| `min_version` | string | No                         | `"1.2"` | Minimum accepted TLS version.          |

```yaml
tls:
  cert_file: "configs/cert.pem"
  key_file: "configs/key.pem"
  min_version: "1.2"
```

`min_version` must be `"1.2"` or `"1.3"`. The certificate and key must be readable and form a valid pair.

---

## `health`

The `health` section configures active checks for every backend in every service.

| Field         | Type    | Required | Description                                                 |
| ------------- | ------- | -------- | ----------------------------------------------------------- |
| `interval_ms` | integer | Yes      | Time between health-check cycles, in milliseconds.          |
| `timeout_ms`  | integer | Yes      | Maximum time to wait for a probe response, in milliseconds. |
| `path`        | string  | Yes      | HTTP path requested on each backend.                        |

```yaml
health:
  interval_ms: 5000
  timeout_ms: 2000
  path: /health
```

`interval_ms` and `timeout_ms` must be greater than zero, and `timeout_ms` cannot exceed `interval_ms`. `path` must be non-empty and begin with `/`.

---

## `observability`

The `observability` section controls Prometheus metrics collection.

| Field     | Type    | Required | Default | Description                 |
| --------- | ------- | -------- | ------- | --------------------------- |
| `enabled` | boolean | No       | `true`  | Enables Prometheus metrics. |

```yaml
observability:
  enabled: true
```

When metrics are enabled, Torus exposes `GET /metrics`. Setting `enabled` to `false` prevents the metrics endpoint from being registered.

---

## `services`

The `services` list defines logical backend pools. Each service has a unique name and one or more upstream URLs.

```yaml
services:
  - name: api
    upstreams:
      - http://localhost:3001
      - http://localhost:3002
```

### `services[].name`

| Property | Value    |
| -------- | -------- |
| Type     | `string` |
| Required | Yes      |

The service name must be non-empty and unique. Routes use this name to select the service.

### `services[].upstreams`

| Property | Value           |
| -------- | --------------- |
| Type     | `array[string]` |
| Required | Yes             |

Every service must define at least one upstream. Each entry must be an HTTP or HTTPS URL with a hostname and an explicit port between `1` and `65535`.

```yaml
services:
  - name: api
    upstreams:
      - http://localhost:3001
      - https://backend.example.com:8443
```

The service owns this pool; Torus selects a healthy backend from it using round-robin load balancing.

---

## `routes`

The `routes` list maps request path prefixes to services.

```yaml
routes:
  - path: /api
    service: api
```

### `routes[].path`

| Property | Value    |
| -------- | -------- |
| Type     | `string` |
| Required | Yes      |

The path must be non-empty and unique. Torus uses longest-prefix matching while respecting path-segment boundaries.

### `routes[].service`

| Property | Value    |
| -------- | -------- |
| Type     | `string` |
| Required | Yes      |

The service value must reference a configured service.

```yaml
services:
  - name: api
    upstreams:
      - http://localhost:3001

routes:
  - path: /api
    service: api
```

---

## Validation rules

Torus validates the entire configuration before it becomes active.

| Area        | Validation                                                                                                                  |
| ----------- | --------------------------------------------------------------------------------------------------------------------------- |
| API version | Must be `v2`.                                                                                                               |
| Server      | `server.addr` must not be empty.                                                                                            |
| TLS         | When configured, certificate and key paths are required; `min_version` must be `"1.2"` or `"1.3"`.                          |
| Health      | Intervals and timeouts must be positive; timeout cannot exceed interval; the path must begin with `/`.                      |
| Services    | Names must be non-empty and unique; each service must have at least one valid HTTP or HTTPS upstream with an explicit port. |
| Routes      | Paths must be non-empty and unique; every route must reference a configured service.                                        |

On startup, a validation error prevents Torus from accepting traffic. During a reload, the current runtime stays active if the new configuration fails validation.

## Complete example

```yaml
apiVersion: v2

server:
  addr: ":8443"

tls:
  cert_file: "configs/cert.pem"
  key_file: "configs/key.pem"
  min_version: "1.2"

health:
  interval_ms: 5000
  timeout_ms: 2000
  path: /health

observability:
  enabled: true

services:
  - name: api
    upstreams:
      - http://localhost:3001
      - http://localhost:3002

  - name: web
    upstreams:
      - http://localhost:4000

routes:
  - path: /api
    service: api

  - path: /
    service: web
```
