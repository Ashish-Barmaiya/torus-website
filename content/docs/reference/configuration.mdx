# Configuration Reference

Torus configuration is YAML. It is validated before a runtime is built; invalid files prevent startup or are rejected during reload.

## Complete structure

```yaml
apiVersion: v2

server:
  addr: ":8080"

health:
  interval_ms: 5000
  timeout_ms: 2000
  path: /health

observability:
  enabled: true

tls:
  cert_file: "/path/to/cert.pem"
  key_file: "/path/to/key.pem"
  min_version: "1.2"

services:
  - name: api
    upstreams:
      - http://localhost:3001
      - http://localhost:3002

routes:
  - path: /api
    service: api
```

## Fields

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `apiVersion` | string | Yes | Current supported value: `v2`. |
| `server.addr` | string | Yes | Listener address in Go `host:port` form. |
| `health.interval_ms` | integer | Yes | Interval between health checks. |
| `health.timeout_ms` | integer | Yes | Timeout for one health-check request. |
| `health.path` | string | Yes | Path requested on each upstream. |
| `observability.enabled` | boolean | No | Enables or disables Prometheus metrics. |
| `tls.cert_file` | string | When `tls` is present | X.509 certificate path. |
| `tls.key_file` | string | When `tls` is present | Matching private-key path. |
| `tls.min_version` | string | No | `"1.2"` or `"1.3"`. |
| `services[].name` | string | Yes | Unique logical service name. |
| `services[].upstreams` | array of strings | Yes | At least one HTTP or HTTPS URL with hostname and explicit port. |
| `routes[].path` | string | Yes | Unique, non-empty path prefix. |
| `routes[].service` | string | Yes | Name of a configured service. |

`tls` is optional. When it is absent, Torus serves HTTP. When present, Torus terminates HTTPS on `server.addr`; client-facing TLS is independent of the scheme used by a service upstream.

## Validation

Torus validates the entire configuration and the relationships between sections:

```text
routes → services → upstreams
```

`server.addr` must not be empty. Health intervals and timeouts must be positive, the timeout cannot exceed the interval, and the health path must be non-empty and begin with `/`. Service names and route paths must be unique; every route must refer to an existing service. Certificate and key paths must be valid when TLS is configured.

## Deployment-specific paths

Certificate paths depend on the deployment. Local configuration can use repository paths, while the systemd installer manages TLS files at:

```yaml
tls:
  cert_file: "/etc/torus/tls/cert.pem"
  key_file: "/etc/torus/tls/key.pem"
```

See [systemd](/docs/deployment/systemd) for that installation model.
